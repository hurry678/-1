# 第三问详细实施计划（正式选择与候选模型版）

## 1. 数据与在线状态

1. 读取附件1—4、7—9；
2. 构图前修订P17为 `Node70, Link507, 303 mm`；
3. 建立600任务的释放时刻和Carrier前序链；
4. 每个决策时刻只传入已释放且Carrier解锁的任务；
5. 复用第一、二问通过审计的路径和0.2 s交通内核。

## 2. 区域压力与微批

1. 按节点编号将轨道划分为区域；
2. 统计可见任务、车辆、Link密度、资源等待和空闲车；
3. 每5 s或累计6个任务触发联合微批；
4. 优先级不低于90的任务即时处理；
5. 枚举车辆及队列插入位置，计算完成时间、空载、队列平方、Port压力、区域边际压力、时隙冲突和迟到风险；
6. 逐项提交最小报价并更新状态。

## 3. 时隙预约与空间接纳

1. 对MERGE、Curve和目标Port生成有限时域时隙；
2. 时隙日历保证同资源计划区间不重叠；
3. 每1 s滚动补充新进入前视范围的资源；
4. 保存计划和实际进入、退出时刻；
5. 实际放行服从物理队首和容量约束；
6. Source距离小于制动接纳距离的空闲车辆候选禁止即时接单；
7. 下游空间不足时由跟驰、停止线和资源权限共同阻止进入。

## 4. 防死锁

1. 每1 s建立静止等待车辆图；
2. 同一环连续出现5次且等待超过10 s才触发；
3. 只撤销最低优先级未载货车辆的未生效预约；
4. 已进入资源或已取货车辆不得撤权和转交；
5. 记录环、车辆、撤销资源和恢复时刻。

## 5. 对比实验

运行四种确定性方案：

1. 直接复用第二问；
2. 普通微批；
3. 压力微批但无显式时隙；
4. 文档完整主模型。

全部方案共用相同任务、路径、物理约束和评价器。正式方案先通过任务完成、连续净空不小于300 mm、运动学、资源、Carrier与在线反事实硬门，再按平均任务执行时间、Makespan和确定性模式名依次择优。本次正式复核仅 `direct` 通过全部硬门，正式值为 AvgTransferTime 854.551420 s、Makespan 4061.8 s；`microbatch` 连续净空为298 mm且有2项硬违规，`pressure` 与 `full` 也因298 mm净空失败，均不得作为正式方案。
