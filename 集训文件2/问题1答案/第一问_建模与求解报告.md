# 第一问：静态任务分配与协同运行

## 1. 问题与数据

第一问包含 32 项初始时刻全部可见的运输任务和 20 辆初始空载 OHT。需要同时确定任务—车辆分配、每辆车的任务顺序、空载路径、载货路径以及冲突通行和速度控制，使平均任务执行时间最小。

数据审计结果为 131 个 Node、152 条启用 Link、36 个 Port、20 辆 OHT、32 项任务、33 个 CurveGroup 和 21 个 MERGE。读取 Port 后、建立路径缓存前，P17 强制修订为 `(Node70, Link507, 303 mm)`。第一问任务不涉及 P17，但公共数据层仍执行并审计该修订。

车辆长度为 950 mm，车尾—车头最小净空为 300 mm。因此，以同一车辆参考点记录位置时，两车最小间距为

\[
d_{\min}=950+300=1250\ \mathrm{mm}.
\]

## 2. 静态取送路径模型

将问题建模为带交通资源约束的静态多车辆取送路径问题（PDVRP-RC）。记任务集合为 \(J\)，车辆集合为 \(K\)，候选有向路径集合为 \(\mathcal P\)。

定义：

- \(x_{jk}\in\{0,1\}\)：任务 \(j\) 是否由车辆 \(k\) 执行；
- \(y_{ij}^{k}\in\{0,1\}\)：车辆 \(k\) 是否在任务 \(i\) 后紧接执行任务 \(j\)；
- \(z_{jq}^{0},z_{jq}^{1}\in\{0,1\}\)：任务空载段、载货段是否选用第 \(q\) 条路径；
- \(A_j,B_j,C_j\)：任务分配、完成取货、完成放货时刻；
- \(e_k(t),s_k(t),v_k(t),a_k(t)\)：车辆所在 Link、Link 内偏移、速度和加速度；
- \(h_{kr}(t)\in\{0,1\}\)：车辆 \(k\) 是否占用互斥资源 \(r\)。

官方目标为

\[
\min \bar T=\frac1{32}\sum_{j\in J}(C_j-r_j).
\]

第一问所有 \(r_j=0\)。Priority 仅用于代理搜索和相同到达时刻的冲突仲裁，不改变官方指标定义。

### 2.1 任务约束

每项任务唯一分配：

\[
\sum_{k\in K}x_{jk}=1,\qquad \forall j\in J.
\]

每辆车同时最多执行一项任务，完成取货后任务与车辆绑定，直至完成放货。第一问没有重复 Carrier，但程序保留通用 Carrier 前后继接口。

### 2.2 路径约束

路径必须沿 Link 的 `FromNodeID→ToNodeID` 方向连续，不得逆行、超车、Link 内掉头或进入 TERMINAL。

当前位置和目标 Port 均按 `(LinkID, offset)` 建模。从位置 \((e,s)\) 到 Port \((e',s')\) 的路径由以下片段组成：

1. 当前 Link 的剩余段 \(L_e-s\)；
2. 当前 Link 终点至目标 Link 起点的完整有向 Link；
3. 目标 Link 的前缀段 \(s'\)。

若目标位于同一 Link 且在车辆后方，则必须沿有向网络绕行，不能直接采用偏移差的绝对值。

### 2.3 运动学与跟驰约束

仿真步长为 \(\Delta t=0.2\) s，采用

\[
v_k(t+\Delta t)=v_k(t)+a_k(t)\Delta t,
\]

\[
s_k(t+\Delta t)=s_k(t)+\frac{v_k(t)+v_k(t+\Delta t)}2\Delta t.
\]

并满足

\[
0\le v_k(t)\le \bar v_{e_k},\qquad -3000\le a_k(t)\le2000.
\]

对同一路径前方车辆 \(f\)，有

\[
d_{kf}^{ref}(t)\ge1250.
\]

控制器将前车视为可以立即制动，并计算下一离散步结束后仍可在剩余距离内以最大减速度停车的速度上界。正式方案采用 710 mm/s 的保守巡航上限；由于这是附件网络的最低 Link 限速，因此逐 Link 限速必然满足，但该设置也意味着结果是可行优化解而非全局最优证明。

### 2.4 Port 与冲突资源

取货和放货各连续占用 Port 8 s，同一 Port 同时最多一车，服务车辆阻断后车穿越。

对任一 MERGE 或 CurveGroup 资源 \(r\)，满足

\[
\sum_{k\in K}h_{kr}(t)\le1.
\]

车辆在可制动前视范围内预约路径前方控制资源。若短 Link 后紧接 MERGE，预约会跨 Link 提前进行，避免进入短 Link 后才发现停车距离不足。MERGE 按下游形成 1250 mm 安全间距后释放；CurveGroup 按车尾完全驶离后释放。

资源仲裁首先遵守单向不可超车关系，即物理队首优先；相同 ETA 时再比较载货状态、任务优先级和车辆编号。空闲车辆为实体并继续合法巡航，但在资源仲裁中低于执行任务车辆。

## 3. 求解算法

### 3.1 基准方案

任务按 Priority 降序、CommandID 升序排列，逐项追加给代理模型中预计完成时间最早的车辆。空载和载货均采用位置感知的自由流最短时间路径。

### 3.2 ALNS 改进方案

将解编码为 20 条车辆任务链。先用全局最小增量插入构造初解，再运行 1200 轮自适应大邻域搜索，随机种子固定为 20260815。

破坏算子包括：

- 随机移除；
- 最差边际贡献移除；
- 相同 Source、Destination 或相近优先级的相关任务移除。

修复采用 regret-3 插入。代理目标为总预计完成时间，并附加轻量优先级迟延、Makespan 和空载距离项。候选解使用模拟退火准则接受；最终候选必须在完整 0.2 s 物理仿真中重新评价。

1200 轮中接受 1119 个候选，发现 46 次历史最好代理解改进。最终比较只使用真实仿真平均任务执行时间，不使用代理目标替代官方目标。

## 4. 最终车辆任务链

最终方案使用全部 20 辆 OHT，其中 8 辆执行 1 项任务、12 辆执行 2 项任务。完整 CommandID 顺序保存在 `outputs/q1/问题1_方案.json`；任务—车辆映射、路径和时间保存在结果工作簿与任务 CSV 中。

## 5. 仿真结果

三套方案均在相同数据、路径、资源和运动学内核下运行，并均通过硬约束审计。

| 方案 | 平均任务执行时间/s | Makespan/s | 完成任务 | 硬违规 |
|---|---:|---:|---:|---:|
| 基准追加调度 | 206.46250 | 406.0 | 32 | 0 |
| 全局增量插入 | 193.08125 | 401.6 | 32 | 0 |
| ALNS 静态调度 | **171.39375** | 332.8 | 32 | 0 |

ALNS 使平均任务执行时间相对基准下降约 16.93%，且是统一硬门通过候选中 AvgTransferTime 最小者，因此选择 ALNS 方案作为第一问正式结果。

附件 9 指标如下：

| 指标 | 结果 |
|---|---:|
| AvgTransferTime | 171.39375 s |
| AvgAssignTime | 0 s |
| AvgPickupResponseTime | 67.33125 s |
| AvgTransportTime | 88.16875 s |
| AvgPausingTime | 1.47500 s |
| Makespan | 332.8 s |
| AvgEmptyDistance | 18014.26875 mm |
| AvgTotalDistance | 79285.559375 mm |
| SimulationRuntime | 0.714585 s |

静态方案在 \(t=0\) 已将全部任务分配到车辆任务链，因此 `AvgAssignTime=0`。这不表示车辆立即取货，排队、空载到 Source、取放货和交通等待均计入 TransferTime。

## 6. 约束审计

最终轨迹包含 1665 个连续时刻、每个时刻 20 辆车，共 33300 行。程序内审计和统一复核脚本均得到：

- 32 项任务全部完成；
- 数据审计错误 0；
- 交通与资源硬违规 0；
- 每个 StepNo 恰有 20 行；
- 最大速度 710 mm/s；
- 最大加速度 2000 mm/s²；
- 最大减速度 3000 mm/s²；
- 采样路径最小参考点间距 1275.000000 mm，对应净空 325.000000 mm；
- 全步长连续最小参考点间距 1275.000000 mm，对应净空 325.000000 mm；
- 取货、放货服务时间均严格为 8 s；
- 时间字段、任务距离、Excel 和 CSV 行数一致。

连续净空证据覆盖同 Link 与跨 Link 车辆对：先沿实际计划路径累计后车至前车的有向距离，再对每个 0.2 s 控制步内的与实际积分一致的分段相对位置函数同时检查两端点及驻点，所得最小参考点距离减去 950 mm 车长。最危险事件发生在 54.491485 s，OHT15 与 OHT10 位于 Link488，连续净空为 325.000000 mm，仍高于 300 mm 硬门。

复现命令：

```powershell
python .\q1_solver.py --iterations 1200
python .\verify_q1.py
```

当前结果是固定种子和固定预算下的零违规可行优化解，不宣称为 32 项静态联合调度问题的全局最优解。后续若继续优化第一问，应优先开放 1000/3000 mm/s Link 上的预测制动速度，并加入多候选路径重选，而不是放宽安全约束。
