# 第二问详细实施计划（文档主模型版）

## 1. 数据准备

1. 读取附件 1—4、6、8、9；
2. 构图前修订 P17 为 `Node70, Link507, 303 mm`；
3. 建立 190 项任务的相对释放时刻和 Carrier 前序链；
4. 分离已释放可分配任务与已释放但 Carrier 阻塞任务；
5. 检查主键、外键、Link 偏移、控制对象和模板行数。

## 2. 模型与算法

1. 采用动态 PDVRP 和 0.2 s交通仿真；
2. 报价包含预计完成、空载增量、等待、历史拥堵、优先级、年龄和队列影响；
3. 对所有车辆和插入位置求报价，使用重复最小报价形成滚动拍卖；
4. 冻结正在执行和已经取货的任务；
5. 未开始任务在承诺期、改善阈值和冷却时间同时满足时允许重排；
6. 预约 Port、MERGE 和 Curve，记录预计进入与授予事件。

## 3. 事件触发

- 新任务到达；
- 放货完成或车辆空闲；
- 有未来队列的任务车到达 FORK；
- 资源等待达到 5 s；
- 等待图成环风险；
- 3 s心跳。

设置 1 s最小重调度间隔、8 s承诺锁定、300 s重排改善阈值和10 s冷却时间。

## 4. 对比实验

统一运行：

1. 在线 FCFS；
2. 滚动最小增量插入；
3. 负载均衡滚动拍卖；
4. 文档完整主模型。

各方案使用相同数据、路径、交通控制和硬约束。先排除未完成、硬违规或未来泄漏方案，再报告平均任务执行时间、Makespan、暂停、距离和运行时间。

## 5. 正式生成

正式方案先通过任务完成、连续净空不小于300 mm、运动学、资源、Carrier与在线反事实硬门，再按平均任务执行时间、Makespan和确定性模式名依次择优。本次正式复核选择 `balanced` 负载均衡滚动拍卖，AvgTransferTime 为 142.946305 s，Makespan 为 3715.2 s；`baseline`、`rolling`、`balanced` 主指标完全平局，`balanced` 仅由确定性平局规则选中。完整保留任务、轨迹、附件9工作簿、在线决策日志、资源预约日志、取货前重分配日志和独立约束审计。
